01选题与定位

招生季的痛点很具体：家长在外地、在上班、在带孩子，来一趟学校要半天；招生老师手里只有一张宣传单和几张照片，说不出"这个专业到底在哪个楼上课"。

这个作品把开放日搬到线上——点开链接就能看校园、看专业、看作品。它不是宣传册的电子版，而是一条可以自己走的路线：七个站点，点开哪一站就看哪一站，最后停在招生信息上。

  • 服务对象：初三学生与家长、招生老师、来校参观的初中学校
  • 使用场景：招生宣传推文里的链接、开放日预约后的提前踩点、外地家长随时查看
  • 与"为学校设计数字形象"的关系：这是学校数字形象里"可进入"的那一层——官网告诉你学校是什么，这里让你走进去
  • 边界：不替代官网的信息发布，不做报名与缴费，预约只做展示与引导

第二版按指导老师的意见改了两处：一是版式的层次（标题、正文、辅助三级在颜色和透明度上分开，细节与对齐重新收过），二是补了一套内容后台——页面里的文字、图片、板块顺序、问答库都能自己改，不用再找人改代码。

第三版（本版）改的是「这个作品到底在回答哪个题目」。老师指出的问题是：五心教育体系在毕设里没有体现，而毕设主题就是五心；同时官网该有的功能性、特别是线上招生这一块，原来只有一个「待定」的时段表，等于没有落地。所以这一版做了三件事：

  • 把五心从「七站末尾的一行小字」提成首页的招牌。首屏右侧五枚印章、首屏下方五等分色带、独立的一整段「五心育人」，点任意一颗心都能展开它的体系表述、在学校长什么样、落在哪几个站、主要养这颗心的专业——这是第 02 节
  • 把线上招生做成能点、能填、能查的四条通道：在线报名登记、预约探校、专业匹配自测、报名进度查询。不是展示，是真的生成报名号和预约码——这是第 03 节
  • 改掉说不通的表述。原来那段「先把数字摆在这里」被老师直接点名，现在改成「六个问题，六个数字答」：先有家长的原话，再给数字，数字是答案而不是开场白

02五心：从标签到招牌

先说上一版错在哪。上一版把五心挂在七站导览每一站的末尾，一行小字：「由此 · 恒心」「由此 · 匠心」。看的人要先读完整站，才知道这里跟某颗心有关；而且五颗心分散在七站里，从头翻到尾也拼不出一个「五心体系」。这本质上是贴标签——老师说「有点勉强附会」，指的就是这个：五心是被后来挂上去的，不是这个作品的骨架。

这一版的改法：五心先立成招牌，再往下长出内容。顺序反过来了——不是「这些地方碰巧能扯上五心」，而是「五心是这所学校的育人体系，所以它在校园里有落点、在专业里有分工、在六年里有顺序」。老师的原话是「张中专五心教育体系在首页，然后点进去可以跳转对应的内容，既是文化的介绍，也在点击和阅读的过程中感受到了五心的内涵」，这一版就是照这句话搭的。

招牌怎么立（首页四层）

层在哪作用
① 印章首屏右侧，竖排五枚五个字先入眼。红底白字，像学校的五枚章；点任意一枚，页面滚到五心段并展开那一颗心
② 色带首屏下方，五等分五心各自的颜色一次铺开，颜色就是导航——后面所有出现五心的地方，用的都是这五个色
③ 体系段「这所学校的金字招牌，是五个字」整段校训、校长寄语、五枚印章、五颗心的详情。这一段是文化介绍本身
④ 贯穿成长路径、系部专业、七站导览、专业自测五心从这里渗到别的段落去：路径图每一步标出哪颗心在起作用，每个专业标出主要养哪颗心，每一站标出落在哪颗心上

点进去看到什么（五颗心的详情块）

五颗心每颗都是一个可展开的块，五块的内容结构完全一致，方便对照着读：

体系表述 官方口径那一句（学校为什么这么提这颗心） 一句话 给家长听的说法（这颗心在学生身上是什么样） 在学校它长这样 三条具体做法，每条一句标题 + 一句说明 落在哪几个站 可点的落点标签，点一下直接跳到七站导览的对应站 主要养这颗心的专业 可点的专业标签，点一下跳到系部专业里那一条 一个数字 这颗心最硬的一个证据

「落在哪几个站」和「主要养这颗心的专业」这两组按钮是关键：五心不是一段读完就过去的文字，它是这张网的一个入口。从五心能去七站，从七站能回五心；从五心能去专业，从专业的五心小签也能回五心。同一个体系，从哪一头进来都走得通。

五心怎么串成一条线（成长路径）

单独讲五颗心，还是五块并列的牌子。所以后面接了一段「从入学到就业，五心一路跟着」：六个节点，每个节点标出这一刻是哪颗心在起作用。这一段解决的是老师说的「东一下西一下，前后对不上」——五心有了时间顺序。

为什么五颗心可以重叠

一颗心对应多个专业、一个专业养多颗心、一站落几颗心——这是故意的，不是偷懒。真实的育人不会把一个人切成五份：一个数控专业的学生，练精度是恒心，做出精品是匠心，进本地企业是红心。所以页面里用的是标签叠加而不是「一个专业归一颗心」的硬分类。也因此，系部专业那一段的筛选器是「按心筛专业」：选「匠心」，剩 9 个专业；选「创心」，剩 10 个——同一批专业会出现在不同的心下面，这正是体系该有的样子。

03线上招生怎么落地

上一版的招生段是空的。五步流程只有第一步有内容，后面四步全写「待定」；场次表三行也全是「待定」。一个招生主题的作品，招生这一段是占位符，等于线上招生这件事没做。老师说「校园官网的功能性要有」，指的就是这个。

这一版把「线上招生」拆成四条通道，每条都做到底：点得进去、填得下去、拿得到号、查得回来。

四条通道

通道解决什么做到什么程度
01 在线报名登记

自测为什么用五心做权重

这是这一版把「功能」和「文化」接起来的地方。常见做法是问「你喜欢动手还是喜欢说话」，然后推荐专业——但那套问卷跟学校的育人体系没关系，换一所学校也能用。这里改成：每个选项加权的对象是五颗心。答完不是给你一个专业，是先告诉你「你身上哪两颗心更明显」，再告诉你「这三个专业主要养的就是这两颗心」。

于是自测的结果天然是一条回到五心的路：测出来是「匠心 + 恒心」，页面上那两颗心的小签可以点，点了就跳到五心段展开那一颗。招生功能和文化介绍在这里不是两件事。

为什么不做真的提交

这个作品是纯静态的，没有后端、没有数据库、也不该收集真实的未成年人信息。所以四条通道的数据全部只存在访问者自己的浏览器里（localStorage），报名号和预约码是本地生成的，刷新还在、清缓存就没了。页面在显眼处写明这一点：预登记不占招生计划、不收费、不替代教育局平台的志愿填报。

这样做的好处是演示时完全可跑：答辩现场在别人的电脑上双击打开就能填、能出号、能查进度，不需要联网、不需要装环境、不会因为服务器没开而演示失败。真要上线，把四个提交函数换成一次 fetch 就行——表单结构、校验、号段规则都已经在了，这是第 09 节「可拓展」里的第一条。

招生这一段还补了什么

  • 五步流程写实了：在线预登记 → 老师回电 → 到校看一次 → 教育局平台填报 → 录取与报到。每一步都写清谁在做什么、家长要准备什么，没有「待定」
  • 三个办学层次说清了：五年一贯制、职教高考、三年制中专，各自适合什么样的学生、后面走什么路
  • 六个高频问题有答案：预登记和正式报名的区别、三个层次怎么选、多少分能进、外地能不能报、能不能留张家港工作、有没有资助
  • 联系方式与二维码：地址、电话、招生咨询中心位置、微信公众号二维码

04结构与交互

整页是一条向下的路线，十段各自解决一个问题，不做并列的卡片堆。这十段的顺序在后台可以调，也可以整段关掉（关掉之后导航里对应的锚点会失效，记得一起改）。

段落解决什么关键交互
首屏三秒说清这是什么，并把五心先亮出来竖排印章、五心印章（可点）、五等分色带、细红压线、向下提示
五心育人五心作为体系讲清楚五枚印章 + 五个 tab + 五个详情块；点印章展开对应那颗心，地址栏带 #heart-red 这样的锚点，可以直接发链接指到某一颗心
校园长卷先把场域铺开两根红漆轴头，滚到这一段自动缓慢向两侧拉开：先逐张翻过 1984—2024 的年份卡，拉到底最后是校门实景
六个问题用可核对的事实建立信任每条先给家长的原话（「学校有多大？」），再是数字；进入视口后数字从 0 补间到实际值
七站导览让人自己决定看哪一站点开一站展开一段，右侧校园示意图高亮对应楼、定位点跟着走；每站末尾挂五心小签，点了跳回五心那一块
系部专业看专业、看办学层次，也能按心找专业六个筛选按钮（全部 + 五颗心，各带数量）；五个系部手风琴，一次只开一个，每个系部标「N 个方向」；每个专业一行，标层次、一句话、主要养的五心
匠心与荣誉看四十年的来路时间线节点逐个亮起，右侧三张新闻图
专业自测二十八选一太难，给个入口六题四选一 → 五心画像条形图 + 最突出的两颗心 + 三个推荐专业 + 两个出口
预约探校把「想来看看」变成「定好哪天来」五个场次带余量条，选场后表单出现在下方，提交出预约码，再给四十分钟到校路线
线上招生把看的人变成报名的人四条通道入口 → 报名表单（六字段 + 专业多选）→ 报名号 → 查进度四步条；五步流程、三个层次、六个问答、地址与二维码

导航只留六项（五心育人、七站导览、系部专业、匠心与荣誉、专业自测、招生报名），右上角一个实心的「在线报名」直接跳到报名表单——这是整页唯一的实心按钮，因为它是这个作品唯一希望访客做的事。手机上导航收进抽屉，五心段从印章改成横排可滑，七站仍是点击展开，示意图缩到列表上方，长卷照旧可以拉开。

另外，右下角常驻一个「问校园」按钮：点开是一层面板，25 组固定问答按关键词命中，答不上来就直说不知道，并建议换个问法或去官网、问招生办。

关于跳转。这一版刻意让几个段落互相能跳，避免「一段一段往下看，看完就过去了」：五心 → 七站、五心 → 专业、七站 → 五心、专业 → 五心、自测结果 → 五心、自测结果 → 报名表单、招生通道 → 四个表单。所有跳转都是页内锚点，不用等加载，手机上也不会跳出去回不来。

05技术实现

前台是纯静态的：一份 HTML、一份 CSS、两份 JS，没有框架、没有外链字体和图标库。把文件夹拷到任何地方双击就能打开，也可以直接放到 GitHub Pages 上。内容单独存在 content.json，由后台改、由前台读，改文案不用碰代码。

  • 内容与页面分离：content.json 是唯一数据源，node tools/build.mjs 把它编译成 assets/js/site-data.js（挂在 window.__CONTENT__ 上）。之所以不直接 fetch 那个 json，是因为 file:// 协议下读本地 json 会被浏览器的同源策略拦掉，双击就白屏；编译成 js 之后双击照样能看
  • 运行时渲染：index.html 是个空壳，assets/js/site.js 按 sections 里的顺序把七段拼出来。后台调顺序、关板块，前台立刻跟着变
  • 卷轴拉开：父级 sticky 占住视口，进入视口 35% 时触发一次，卷面宽度用 6 秒过渡从 5% 走到 100%，边拉开边翻帧，翻到最后停在门面图
  • 七站展开：点标题给该条加 .is-open，用 grid-template-rows: 0fr → 1fr 做高度过渡，同时把示意图对应楼高亮、定位点移过去
  • 示意图联动：SVG 每块写 data-block，JS 按名字找块，把定位点移到块的右上角，标签同时转白
  • 数字补间：IntersectionObserver 只触发一次，rAF 里按 easeOutCubic 跑 1300ms
  • 问校园：每条问答有关键词表，访客的话去和关键词比对，命中词越长、命中个数越多得分越高，再叠一个后台可调的权重；最高分低于阈值就当答不上来，如实说不知道，并建议换个问法或去学校官网、问招生办
  • 版式层次：全站分三级——标题深黑、正文中灰（对墨色 74%）、辅助更淡（48%），透明度和字距同步拉开，灰阶全部由主色 mix 出来，换了主色层次不会散
  • 优雅降级：系统开启"减少动态效果"时，所有过渡与视差关闭，内容直接呈现
  • 五心切换：五颗心是同一段里的五块，只有一块带 .is-on。点印章或 tab 时只做两件事——换 .is-on、用 history.replaceState 把地址栏改成 #heart-red。用 replaceState 而不是 pushState，是为了让「返回」还是回上一页，而不是在五颗心之间倒退
  • 按心筛专业：每个专业行带 data-hearts="jiang heng" 这样的空格分隔串，筛选就是拿 indexOf 比一下，命中就显示、不命中就 hidden。没有重新渲染 DOM，所以切来切去不闪、也不丢展开状态
  • 自测算分：每个选项带一个五心权重对象，答完把六次选择累加，得到五维分；取最高的两颗心，再从专业表里筛「主要养这两颗心」的专业，按命中数排序取前三个。全程是加法，没有模型、没有随机数，同一组答案永远同一结果——答辩时可以当场重做一遍验证
  • 报名号与预约码：都是本地生成的。YT + 年月日 + 两位序号，序号取当天已有条数；预约码是 V + 场次 id + 四位随机。存进 localStorage 的 yyt_apply_v1 / yyt_visit_v1，查进度时用报名号 + 手机号双匹配
  • 表单校验：不引第三方校验库。姓名非空、手机正则 ^1\d{10}$、学校非空，哪一项不对就把焦点移过去并在该项下面写一句话，不弹 alert
  • 可访问性：语义化标签、aria-expanded、键盘可聚焦、正文对比度按 AA 校对；五心印章是 <button> 不是 div，屏幕阅读器能读出来

08内容后台

老师提了一个很实际的问题：这个页面是死的，招生办想换句话、换张图、加一条问答，都得找人改代码。所以补了一套后台。后台有两种开法，界面完全相同，只是保存通道不同：免安装模式把内容存在浏览器里、再导出两个文件；本地服务模式直接写本机文件。

怎么开（两种都可以）

① 免安装：双击 源码\admin\index.html ← 什么都不用装 口令 首次是 admin123 保存后内容存在这台电脑的浏览器里，前台刷新即变 点「导出文件」下载 content.json 与 site-data.js，覆盖回 源码 即可带走 ② 本地服务：双击 源码\启动后台.bat ← 要装了 Node 前台 http://127.0.0.1:7717/ 后台 http://127.0.0.1:7717/admin/ 等价做法：cd 源码 && node server.mjs

免安装模式为什么能成立：内容不是存在服务器上，而是存在浏览器的 localStorage 里；前台在 file: 下打开时先看这里有没有覆盖内容，有就用它。所以双击就能改、改完刷新就见，全程不联网、不装东西、也不需要任何账号。要换电脑或交给别人，点「导出文件」把两个文件覆盖回去即可。

后台启动时先判断打开方式：127.0.0.1 / localhost 走本地服务模式（口令登录、POST 到 server.mjs）；其他方式（双击文件、或从普通网址打开）走免安装模式。同一份 admin.js，中间用一层 NET 抽象把「读」和「存」换掉，界面代码一行都不用分叉。

本地服务模式只用 Node 自带的 http / fs / crypto 三个模块，不装任何依赖，不用数据库——内容就是 content.json 这个文件本身。免安装模式连这一步也省了，代价是内容在浏览器里，所以给了「导出文件」当出口。

三个页面各管什么

页面能改什么对应老师说的哪一条

为什么这么设计

  • 后台不接管前台：后台只写 content.json，前台只读编译好的 site-data.js。关掉服务，前台照样双击能看，也能扔到 GitHub Pages 上
  • 问答是可编辑的数据，不是模型：没有调用任何在线大模型，判断靠关键词匹配加权重。好处是断网能用、答什么完全可控、不会瞎编；代价是问法太偏就答不上来——所以新增问答时关键词要写全，把家长可能的问法都列进去
  • 登录够用就行：本地服务模式的口令用 scrypt 加盐存哈希，会话放在内存里，服务只听 127.0.0.1；免安装模式的口令只比对浏览器里存的一个值——它本来就不是安全边界，只用来挡住「随手点开就改」的误操作。这是两个人用的规模，不做多账号体系
  • 新增的三段一开始就按后台可编辑来写：五心、自测、预约不是把文案写死在 site.js 里。五心的体系表述、三所学校里的做法、落点、专业对应；六道题的题干、四个选项、每个选项对五颗心的权重；五个场次的日期、时段、名额、已约人数——都在 content.json 里，后台改得动。招生办的老师要加一场开放日，只要在后台按「+ 增加一条」填日期和名额，前台刷新就有
  • 顺手补的两处安全：静态文件走白名单，server.mjs、口令文件、版本快照不会被当网页发出去；上传只收图片并限制大小

答辩时怎么演示

开两个窗口：左边后台改一句文案、点保存；右边前台刷新，字变了。再到「板块排版」把纸色从宣纸换成米白、主红换成胭脂，保存后前台马上换色；最后打开「问答库」加一条新问答，回前台问一句，答案就出来了。这一套在别人的电脑上也能现场演示——双击 admin/index.html 就能开，那台电脑什么都不用装；演示完点「导出文件」把改动带走。

改完怎么上线

线上挂在 GitHub Pages：展厅 https://gxglad.github.io/yyt/，仓库 github.com/gxglad/yyt，主分支 main，Pages 直接读仓库根目录——而仓库根目录就是这个「源码」文件夹。所以不用再往别处拷文件，在 源码 里提交推送就等于发布：

node tools\build.mjs ← 改过 content.json 才需要（后台保存会自动做） git add -A git commit -m "改了什么" git push origin main ← 本机要走代理，见说明.txt 第五节的完整命令

免安装模式改完的内容在浏览器里，所以有一件事要做：点一次「导出文件」，把 content.json 和 site-data.js 覆盖回 源码。导出的 site-data.js 与 tools/build.mjs 生成的是同一种格式，所以覆盖后可以直接推，也可以再跑一遍构建确认。

为什么不让浏览器直接提交仓库：那要给每个用后台的人发一个仓库写权限的 token，等于把仓库交出去。毕设交付的对象是学校，账号体系不该绑在开发者身上，所以选「浏览器存 + 导出文件」这条不依赖任何账号的路。

09可拓展

  • 四条通道接真实后端：现在报名号、预约码都在访问者自己的浏览器里。把四个提交函数换成一次 fetch，回执进招生办的表格，就成了真能用的招生登记
  • 专业匹配自测加权重校正：六道题的五心权重现在是按专业分布估的，跑一段时间后可以拿真实报名数据回校一遍，让推荐更准
  • 问答库接一个在线模型做兜底：关键词没命中时让模型按已有答案的范围改写，仍然答不上来才说不知道
  • 后台加多账号与操作日志，招生办几个人一起用
  • 加一段 30 秒无声循环视频替换长卷，弱网下退回图片
  • 英文版与繁体版，服务外籍家长与港澳台招生
  • 五心做成可分享的专题页：一颗心一个链接（现在是 #heart-red，已经能指到，但还在一页里），班主任可以直接把「仁心」这一颗心发给家长
  • 接入校园实景全景图（全景相机拍摄的 8K 等距柱状图），做成可拖拽的 360° 站点
